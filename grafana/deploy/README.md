# Grafana monitoring stack for Odoo

Ready-to-run Docker Compose stack for the `grafana` Odoo module.

```
 Odoo workers ──/metrics──► Prometheus ─┐
 (grafana module)                       │
 /var/log/odoo/*.log ──► Alloy ──► Loki ├──► Grafana ──(iframe, /grafana/)──► Odoo backend
 PostgreSQL ──► postgres-exporter ──────┤
 PostgreSQL (grafana_ro, read-only) ────┘
```

| Piece | Role |
|---|---|
| `grafana` Odoo module | `/metrics` endpoint, slow request/query log, JSON logs, embedded dashboards |
| Prometheus | scrapes Odoo and postgres-exporter, 30 days retention |
| Alloy → Loki | ships the Odoo log file, 30 days retention |
| Grafana | 4 provisioned dashboards in the *Odoo* folder, served at `/grafana/` |

| File | |
|---|---|
| `docker-compose.monitoring.yml` | the stack, layered on top of the compose file that runs Odoo |
| `prometheus/prometheus.yml` | scrape targets |
| `loki/loki.yml`, `alloy/config.alloy` | log storage and shipping |
| `grafana/provisioning/` | data sources (Prometheus, Loki, Odoo PostgreSQL) and dashboard provider |
| `grafana/dashboards/*.json` | dashboards, generated by `grafana/build_dashboards.py` |
| `postgres/` | read-only `grafana_ro` role for Grafana and postgres-exporter |
| `nginx/grafana.conf` | nginx locations serving Grafana under `/grafana/` and hiding `/metrics` |

## Requirements

The stack expects an Odoo deployment with Docker Compose where:

* the Odoo service is called `odoo` and PostgreSQL `db` (otherwise adjust
  `prometheus/prometheus.yml`, `grafana/provisioning/datasources/datasources.yml`
  and `docker-compose.monitoring.yml`);
* PostgreSQL is version 13 or later;
* the Odoo image has `prometheus-client` installed
  (`RUN pip install prometheus-client` in its Dockerfile);
* nginx (or another reverse proxy) sits in front of Odoo, so Grafana can be
  served on the same domain. The embedded view relies on it: the Grafana
  session cookie is only sent to the iframe from the same origin.

## First setup

1. Copy this folder next to your `docker-compose.yml` as `monitoring/`, and
   the compose file next to it:

   ```
   cp -r <addons>/grafana/deploy ./monitoring
   cp monitoring/docker-compose.monitoring.yml .
   ```

2. Odoo configuration file:

   ```
   server_wide_modules = base,web,grafana
   grafana_log_json = True
   logfile = /var/log/odoo/odoo.log
   ```

3. Add to `.env`:

   ```
   ODOO_DB=<your database>
   GRAFANA_ADMIN_PASSWORD=<strong password>
   GRAFANA_DB_PASSWORD=<strong password>
   # links generated by Grafana use http://GRAFANA_DOMAIN:ODOO_PORT/grafana/
   # (behind HTTPS, set GF_SERVER_ROOT_URL in docker-compose.monitoring.yml)
   GRAFANA_DOMAIN=odoo.example.com
   ODOO_PORT=8069
   # optional, see "Securing /metrics"
   ODOO_METRICS_TOKEN=
   # optional, so plain `docker compose` includes the stack
   COMPOSE_FILE=docker-compose.yml:docker-compose.monitoring.yml
   ```

4. Add the locations of `nginx/grafana.conf` to the nginx `server` block of
   Odoo.

5. Rebuild the Odoo image if needed and start everything:

   ```
   docker compose -f docker-compose.yml -f docker-compose.monitoring.yml up -d --build
   ```

   `db` restarts once to preload `pg_stat_statements`.

6. Install the **Grafana** app in Odoo (Apps menu, or `-i grafana`).

7. Create the read-only role for Grafana and postgres-exporter (needs
   `POSTGRES_USER` in `.env`; re-run after installing modules whose tables a
   dashboard uses):

   ```
   ./monitoring/postgres/setup-grafana-role.sh
   ```

8. Open `https://<your domain>/grafana/` (admin / `GRAFANA_ADMIN_PASSWORD`),
   or in Odoo: **Grafana → Dashboards**. Log in to Grafana once in the
   browser; the embedded view reuses that session.

## What to look at when optimising

* **Performance → Time spent per route / Most expensive model methods**: where
  worker time goes. Start optimising at the top.
* **SQL queries per request by route**: hundreds of queries per request is the
  classic N+1 (`for rec in records: rec.x_id.name`) → prefetch, `read_group`,
  `mapped()`.
* **Share of request time spent in SQL**: low share + high latency means Python
  (computes, rendering), high share means queries/indexes.
* **Grafana → Performance → Slow Requests / Slow Queries** in Odoo: each slow
  call with its user, model.method, SQL count and the slow queries themselves
  (group by *Query Fingerprint*).
* **PostgreSQL → Top queries / Sequential scans / Unused indexes**: missing or
  useless indexes (`index=True` on fields used in domains).
* **Logs → Heavy requests**: access-log lines with > 100 queries or > 2 s.

Thresholds and retention: **Settings → Grafana**.

## Securing /metrics

`nginx/grafana.conf` returns 404 for `/metrics`; Prometheus scrapes `odoo:8069`
on the internal docker network. To also require a token, set
`ODOO_METRICS_TOKEN` in `.env`, write the same value to
`monitoring/prometheus/odoo_metrics_token`, mount it in the prometheus service
(`./monitoring/prometheus/odoo_metrics_token:/etc/prometheus/odoo_metrics_token:ro`)
and uncomment the `authorization` block in `prometheus.yml`.

## Log file size

Odoo never rotates its log file. Rotate it with logrotate, using `nocreate`
(Odoo reopens the file by itself after it is renamed) and `delaycompress`
(Alloy may still be reading the previous file):

```
/var/log/odoo/*.log {
    daily
    maxsize 200M
    rotate 14
    compress
    delaycompress
    missingok
    notifempty
    nocreate
}
```

Prometheus and Loki keep 30 days (`--storage.tsdb.retention.time`,
`retention_period`), slow request logs follow *Settings → Grafana → Log
Retention*.

## Changing dashboards

Dashboards are generated: edit `grafana/build_dashboards.py`, then
`python3 monitoring/grafana/build_dashboards.py`. Grafana reloads the files
within a minute. Dashboards built in the Grafana UI should go in another
folder (the *Odoo* folder is read-only).

## Running without Docker

`pip install prometheus-client`, then in the Odoo config:

```
server_wide_modules = base,web,grafana
grafana_log_json = True
```

With `workers > 0`, also export `PROMETHEUS_MULTIPROC_DIR` to an empty
directory, wiped at each start, otherwise each scrape only sees one worker.
Point your own Prometheus at `http://<odoo>:8069/metrics` and import the JSON
files of `grafana/dashboards` (data source UIDs: `prometheus`, `loki`,
`odoo-postgres`).
